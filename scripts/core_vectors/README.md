# Bitcoin Core's script test vectors

Runs the engine against Bitcoin Core's own consensus test vectors and reports every disagreement.

| File | Source | Checks |
| --- | --- | ---: |
| `script_tests.json` | [bitcoin/bitcoin](https://github.com/bitcoin/bitcoin/blob/master/src/test/data/script_tests.json), `src/test/data` | 1,258 |
| `script_assets_test.json` | [bitcoin-core/qa-assets](https://github.com/bitcoin-core/qa-assets/blob/main/unit_test_data/script_assets_test.json), `unit_test_data` | 3,737 |

`script_tests.json` covers legacy, P2SH and segwit v0 scripts under many flag combinations.
`script_assets_test.json` is generated by Bitcoin Core's `feature_taproot.py`: 2,244 transactions,
each with a valid witness for one input and, for 1,493 of them, an invalid one.

## Running

Needs Scarb 2.19.6 and Python 3. Execution needs Linux or macOS only if you also prove; running
the vectors works anywhere Scarb does.

```bash
curl -fsSLO https://raw.githubusercontent.com/bitcoin/bitcoin/master/src/test/data/script_tests.json
curl -fsSLO https://raw.githubusercontent.com/bitcoin-core/qa-assets/main/unit_test_data/script_assets_test.json
python3 vectors.py script_tests.json script_assets_test.json cases.jsonl
(cd harness && scarb build)
cd harness && python3 ../run.py ../cases.jsonl ../results.jsonl --jobs 8 --batch 4
python3 ../summarize.py ../results.jsonl
```

`run.py --filter TEXT` and `--exclude TEXT` select cases by id or description.

## How a case is checked

`vectors.py` builds each case the way Bitcoin Core's `script_tests.cpp` does:

- for `script_tests.json`, a one-input transaction spending a crediting transaction
  (`BuildCreditingTransaction` and `BuildSpendingTransaction`), with scripts parsed by a port of
  `ParseScript`, and the `#SCRIPT#`, `#CONTROLBLOCK#` and `#TAPROOTOUTPUT#` placeholders filled
  in as Core does (a single tapscript leaf under the NUMS internal key);
- for `script_assets_test.json`, the given transaction with the "success" or "failure" witness
  substituted at the given input, checked under the entry's own flags.

The `harness/` executable deserializes the transaction, runs `EngineImpl` on the input, and
returns `'VALID'` or the engine's error. `run.py` runs cases in batches and reruns a batch that
panics one case at a time.

Each check is classified against Bitcoin Core:

- **soundness**: Core rejects the input and the engine accepts it. These matter most: they are
  spends the engine would let through.
- **completeness**: Core accepts the input and the engine rejects it or panics.
- A panic on an input Core rejects counts as agreement.

Flags matter for interpreting a failure. Consensus flags on mainnet today are P2SH, DERSIG,
NULLDUMMY, CHECKLOCKTIMEVERIFY, CHECKSEQUENCEVERIFY, WITNESS and TAPROOT; every other flag is a
relay policy. `summarize.py` reports the two separately.
